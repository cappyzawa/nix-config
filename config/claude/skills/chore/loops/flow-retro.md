# flow-retro

## 目的

レビュー層（diff-review / codex / verify / PR レビュー）の取り逃し記録を集計し、層の設定を調整する提案を作る。

## 発見

- `~/.claude/retro/flow.md` を読む。**このファイルは未処理キューなので、`^- ` で始まる行すべてが対象**（見出し・空行はキューに含めない）
- ファイルが無い・エントリ 0 件なら仕事なし
- **`~/.claude/retro/archive.md` は読み込まない。** 処理済み履歴で、必要なのは再発判定の grep だけ（下記）

## 実行

この loop の「1 件」は raw entry ではなく `should-have` と `kind` の組で作る pattern group:

1. キューのエントリを `should-have` × `kind` で group 化する
2. **各 group について archive.md を grep し、過去に同じ形が何回出ているかを数える。** キュー内 1 件でも過去に 1 件以上あれば「別タスクで再発」に当たるので調整対象にする（CLAUDE.md「指摘事項の扱い」の昇格条件）
3. 2 件以上（キュー + archive の合計）ある group について調整案を作る:
   - `diff-review` で捕まえるべきだった → `diff-review` skill の観点の追加、または land のレビュー手順への追加を提案
   - `codex` で捕まえるべきだった → codex skill のレビュー観点への追加を提案
   - `verify` で捕まえるべきだった → verify skill の surface 観点表、または譲れない点への追加を提案
   - `scope` → 省略不可リスト（CLAUDE.md）への追加を提案
   - `none` → 既存のどの層も所有していない。層の新設・拡張を提案するか、所有者が無いままである理由を述べる
   - `plan` → 層は 2026-08-05 に撤去済み。提案せず archive へ送るだけ（義務は §gap を測る / §ループ / verify へ移設した）
4. **バグ種別を観点として列挙しない。** race・ランタイム内部・CSS 詳細度のような分類を足すと、レビューの観点が「大きい誤りを探す」からチェックリストに変わって効かなくなる。足すのは、レビュアーが**構造的に見落とす形**（変更した箇所では diff が完成して見える等）に限る
5. 調整案は nix-config の `config/claude/` への変更として出す。文脈依存で汎化できないエントリは提案せず archive へ送るだけ

## 検証

- 提案した文言の根拠が archive / キューの実エントリに対応していることを示す（何件・どの repo か）
- 人間のレビュー（PR を作る場合は title / body を英語で）

## 記録

- 処理したエントリを `~/.claude/retro/archive.md` の末尾へ移す。行末に `<!-- triaged YYYY-MM-DD: <結果> -->` を付けてから移す
- **移したら flow.md から消す。** キューは未処理だけが残る状態にする（処理済みが混ざると次回また読むことになる）
- archive.md の既存行は編集しない。層の改名にともなう語彙の一括置換だけは、判定を変えないので行ってよい

## 上限

- 1 回の実行で pattern group 3 件まで（提案に含める group 数の上限）
- 提案しなかったエントリも archive へ送る。**キューに残すのは、次回に持ち越して判定したいものだけ**
