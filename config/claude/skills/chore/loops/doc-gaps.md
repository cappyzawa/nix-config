# doc-gaps

## 目的

各セッションが auto memory の doc-gaps.md に記録した「ドキュメントから読み取れなかった暗黙知」を、正式なドキュメントに昇格させる。

## 発見

- 現在のプロジェクトの auto memory ディレクトリ（システムプロンプトに記載）にある `doc-gaps.md` を読む
- 「## processed」節に入っていないエントリが未処理
- ファイルが存在しない、または未処理ゼロなら仕事なし

## 実行（1 件ごと）

1. エントリを読み、3 択に分類する:
   - **文書化**: 行き先を決める — プロジェクトの規約・アーキテクチャは AGENTS.md / CLAUDE.md、ドメイン知識・用語は docs/、ファイル局所のルールは .claude/rules/（`paths:` でスコープ）
   - **破棄提案**: 一時的な混乱だった・その後コードから自明になった等。ファイルは変更せず、理由を付けて PR description に列挙する
   - **要人間**: ドメイン判断や優先順位の判断が必要。推測で文書化せず、質問の形で PR description に列挙する
2. 文書化する場合、既存ドキュメントの文体・構成・言語に合わせて書く。エントリの「何を知りたかったか」が見出しの種、「どこを探したか・どう判断したか」が本文の種になる

## 検証

- lint（markdownlint 等）がプロジェクトに設定されていれば通す
- 最終検証は人間の PR レビュー。したがって PR は必ず draft で作る

## 記録

- feature branch を切り、文書化エントリの変更をリポジトリごとに 1 本の draft PR にまとめる（公開リポジトリでは PR title / body は英語）
- 処理した全エントリ（文書化・破棄提案・要人間とも）を doc-gaps.md の「## processed」節へ移動し、分類と PR の URL を付記する
- 破棄提案と要人間は人間が PR 上で裁く。回答が出たら次回のループまたは人間が反映する

## 上限

- 1 回の実行で 3 件まで
