# Root fix

継ぎ足しの修正は差分量で必ず勝つので、比較を出さない限り既定になる。
この skill は比較を出すところまでを担い、実装はしない。
AGENTS.md の調査依頼と同じ扱いで、結論と根拠で終える。

## 1. 修正の形を読む

変更しようとしている箇所に加えて、それを呼ぶ側と、同じ責務を持つ兄弟のコードを読む。
これから当てる修正が次のどれに当たるかを判定する。

- 条件分岐、flag、特例を足して特定の入力だけ振る舞いを変える
  - 型が表せない状態を実行時に選り分けている形で、Make illegal states unrepresentable の逆である
- 既存のパターンを複製して、似た処理がもう 1 つ増える
  - 同じ不変条件を 2 か所で守っている形で、Once and only once の逆である
- 同じ趣旨の変更を複数の呼び出し元に同時に入れる
  - Shotgun surgery と呼ばれる形である
- 呼び出し側で、被呼び出し側の欠陥や欠けている保証を補う
  - 検査結果が型に残らず下流が再検査している形で、Parse, don't validate の逆である

どれにも当たらなければ「継ぎ足しではない」と結論して終える。

## 2. 構造側の候補を出す

1 で当たった形はどれも、ある不変条件を誰かが手で守っている状態である。
その不変条件が何で、今は誰が守っているかを 1 文で言う。
構造案は、その不変条件を構築時に成り立たせる形に移す案で、置き場所は次の 3 つのいずれかになる。

- 型で表す
  - 状態なら sum type で不正な組み合わせを作れなくする（Make illegal states unrepresentable）
  - 入力なら検査を通った値だけ別の型で返す（Parse, don't validate）
- 責務の境界の内側に閉じ、外から不変条件を壊せる経路を無くす
- 被呼び出し側が保証し、呼び出し側の補いを消す（Tell, don't ask）

型や signature に触るので呼び出し元へ波及し、差分は症状案より大きくなるのが普通である。
候補は 1 つか 2 つに絞り、それ以上は挙げない。

## 3. 並べる

症状を足す案と構造を直す案を、同じ軸で表にする。

| 軸 | 見ること |
|---|---|
| 触るファイル集合 | 書き込み先の一覧と、公開 API や保存形式に触れるか |
| 次の同種修正 | 構造案を選ぶと、どの種類の修正が今後要らなくなるか |
| 既存テストの守り | 変更範囲のうち、どこまでを既存テストが検出するか |
| 影響範囲 | 呼び出し元の数と、外部から見える振る舞いが変わるか |

「次の同種修正」は、コードから具体的に予見できるものだけを書く。
想像上の将来要件で構造案を推さない。

## 4. 推奨して止まる

推奨を 1 つ選び、理由を 1 文か 2 文で添える。
選ぶ軸は差分量ではなく、次の同種修正が要らなくなるかと既存テストが守る範囲である。
構造案が新規依存の追加か既存の設計方針の変更に当たるなら、その旨を明記する。
ユーザーが選ぶまで実装に入らない。
