# 応答の組み立て

ユーザーは経過の実況より、結論とその根拠を読みたい。
応答は次の順で組み立てる。

- 最初の段落で、問いへの答えか、作業の結果を述べる。
- 次に、その結論を支える根拠を書く。根拠は、読んだコード、実行した出力、ユーザーの発言のどれかを示す。
- 確かめていないことは、推測か提案として書き、断定と混ぜない。
- ユーザーが判断すべきことや次に取れる行動があれば、最後に置く。

経過は、結論の理解に要る判断だけを書き、手順の逐一は書かない。
見出し、表、箇条書きは、内容に構造があるときだけ使い、短い答えは散文で書く。
ユーザーが説明や詳細を求めたときは、短さより網羅を優先する。

英語で書くとき（public repository の PR や commit message など）は、日本語固有の整形規則を除いて、論証と冗長の規範だけを適用する。
